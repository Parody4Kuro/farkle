# 构筑验证与参数记录

日期：2026-09-12。规则实现、自动化对局和代理操作检查已经执行；项目主人的个人试玩尚未进行。下面的胜率用于发现原型问题，不作为真人胜率或最终平衡结论。

## 当前规则与调整依据

首版存档评分版本为 1。三个核心均占用一个徽章位、至多同时佩戴一个；所有计分代价仍保持合法组合得分为正。经典模式保持原有四种普通徽章。

| 核心 | 收益 | 代价 | 可复现例子 |
| --- | --- | --- | --- |
| 铜筹账簿 | 单骰 1、5 ×2 | 同点、顺子 ×0.5 | 三个 1 拆为三个单骰共 600，比三同的 500 高；三个 3 仅 150 |
| 同契纹章 | 三至六同 ×1.5 | 单骰、顺子 ×0.5 | 三个 5 得 750；单颗 5 仅 25 |
| 歧路罗盘 | 顺子 ×3；含 Joker 的同点组 ×2 | 不含 Joker 的同点组 ×0.75 | 1–5 得 1500；3、3、Joker 得 600；三个 3 仅 225 |

原计划中的罗盘原型使用“顺子 ×2、普通同点 ×0.5”。60 种种子、常规策略、六颗公平骰的第一桌对照中，原型获胜 36.7%，无核心 56.7%；普通旅人整夜通关 35.0%。它在尚未获得 Joker 时过于依赖稀少的有利局面，因此仅调整顺子收益和普通同点代价，未赠送额外骰子、改变加权概率或奖励数量。原始结果保留在 [原型数据](build-simulation-prototype.json)，其中版本 1 是尚未交付前的开发原型，不应与当前倍率混合统计。

最终参数在两个不重叠的 120 种种子集合中复验；另补充保守策略。对应脚本是 [simulate-builds.ts](../scripts/simulate-builds.ts)，原始结果为 [主样本](build-simulation.json)、[独立种子](build-simulation-holdout.json) 和 [保守策略](build-simulation-conservative.json)。主样本文件的置信区间说明由旧的 60 行样本文案修正为实际 120 次，结果数值未改动。

## 方法与边界

- 每组种子为 `seedBase + i × 7919`，主组从 18017 开始，独立组从 970003 开始。全部调用正式纯 reducer、装备评分 DFS 和加权随机。相同初始种子下，策略会消耗不同数量的随机数，不能视为逐手共享骰面的配对实验。
- 整夜覆盖三种起始套装 × 三种核心，每行 120 夜；按常规风险策略选择当前最高合法收益，使用真实奖励、持有数量、入座整备和同桌重试。保留开局核心用于测量该方向，普通徽章优先护符、满载，其后按核心偏好排序骰子，再考虑黄金一点和翻倍。脚本给出了全部排序。
- 单桌分别检查公平骰第一桌、商路旧识老板桌、夜行旅人再获得一颗 Joker 的老板桌。老板装备是可由三次奖励获得的条件对照，不代表实际抽到这些奖励的概率；每个配置各自可达，并遵守六骰、两徽章、一核心上限。只有两配置的装备并集也符合三次奖励预算时，才将它们解释为同一背包内的取舍；双 Joker 再加三种普通徽章的并集不满足这一条件。
- 单桌包含常规、冒险、保守三种公开风险阈值。黄金一点选立即收益提升最大的目标，孤注一掷在当前选择至少 350 分或能立即获胜时使用。它们是启发式策略，不是求解后的最优策略。
- 最终数据合计 2160 个不同的完整夜配置与种子组合、22800 次单桌配置与种子组合。保守文件中的 1080 夜是独立组常规整夜的重复运行，未重复计入。所有模拟结束，无步骤上限或存档一致性断言失败；每行第一种子的每次状态转换均检查序列化恢复、随机流、待演出结果与装备数量。
- 记录胜负、平均落袋、投掷数、爆骰率、组合种类、与无核心选择的差异、能力次数及重试数；每条整夜样例另保留奖励和最终装备。脚本没有测量真人思考时间、演出舒适程度，也没有穷尽所有奖励策略和核心转型。
- 每行 120 次时，50% 比例的近似 95% 二项误差约 ±9 个百分点；这里只报告描述性差异，未做多重比较校正，不能凭几个百分点排序核心。

复现当前比较：

```bash
node --import tsx scripts/simulate-builds.ts 120 18017 /private/tmp/build-main.json
node --import tsx scripts/simulate-builds.ts 120 970003 /private/tmp/build-holdout.json
node --import tsx scripts/simulate-builds.ts 120 970003 /private/tmp/build-conservative.json conservative
```

## 观察结果

以下为独立种子的常规策略结果，每格 120 次。

| 起始条件 | 铜筹账簿 | 同契纹章 | 歧路罗盘 |
| --- | ---: | ---: | ---: |
| 六公平骰，第一桌获胜 | 60.8% | 64.2% | 60.0% |
| 普通旅人，整夜通关 | 46.7% | 48.3% | 48.3% |
| 商路旧识，整夜通关 | 44.2% | 47.5% | 50.0% |
| 夜行旅人，整夜通关 | 53.3% | 65.8% | 79.2% |

无核心六公平骰第一桌为 60.0%。主组中这一行依次为无核心 59.2%、账簿 69.2%、纹章 63.3%、罗盘 61.7%。罗盘的无 Joker 开局弱势得到缓解；它与 Joker 起始套装的协同明显更强，后续真人试玩应重点关注这种强度是否压缩奖励取舍。

核心的决策差异并不等同于每次选中不同的骰子。账簿在独立组普通旅人整夜的 13.3% 选骰阶段改变了所选骰或组合拆分；纹章为 0.9%，罗盘为 0.2%。后两者常常仍取相同的合法组合，主要改变该手收益、继续阈值与装备偏好。当前证据支持有条件的数值与选骰差异，尚不能证明三种都具有足够的长期策略深度。

同一老板桌、同一商路骰组下，护符加满载是很强的无核心组合：独立组常规策略获胜 90.0%；纹章加黄金一点为 91.7%，罗盘加满载为 93.3%，账簿加黄金一点为 84.2%。在同样实际可获得的背包中，双 Joker 老板桌的护符加满载为 95.8%、罗盘加满载为 99.2%（核心免费，两种普通徽章与第二颗 Joker 共三次奖励）。没有观察到护符加满载在所有已测场景普遍压过核心，但账簿在这种后期组合中的胜率较弱，不能因此宣称不存在其他支配配置。

保守策略下，公平骰第一桌无核心 56.7%、账簿 50.8%、纹章 61.7%、罗盘 55.8%。账簿的名字并不意味着应该总是小额落袋；较高的单骰收益配合相同保守阈值，可能过早结束回合。这也是个人试玩应判断的策略取舍。维持当前三个核心与原奖励数量，暂不通过增加装备掩盖差异。

## 已执行的操作检查

通过可见操作验证开局选择、换装、获胜领奖、同桌重试和整夜通关；浏览器与实际 `.app` 的最终结果见 [回归记录](validation.md)。核心卡片、暂停对话框及 1280×720 整备布局经过代理视觉检查。过程中修复了整备面板重叠、悬停位移导致按钮在鼠标边界反复移动，以及掷骰后键盘焦点丢失。

键盘路径使用 Tab / Shift+Tab（macOS WebKit 使用 Option-Tab）、回车、空格和原生下拉选项的数字首字定位，覆盖核心换出换回、选四个 1 以纹章落袋 3000 分、领奖换骰、暂停和手动继续。没有把 `selectOption` 或强制点击当作这条路径的键盘验收。
