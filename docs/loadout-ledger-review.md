## 2. 建议的换装方案

**公平骰作为基础物品始终保有六颗，特殊骰另计；装备数量和持有数量分别显示。**

1. 新夜库存登记六颗基础公平骰，再登记起始套装中的特殊骰。初始装备仍按所选套装配置。例如商路旧识持有八颗：公平骰六颗、工匠之五一颗、高地骰一颗，装备其中六颗。
2. 读取合法旧档时，将不足六颗的基础公平骰补足。使用幂等迁移，重复读取不会继续增加库存。保留特殊骰、徽章、当前桌、比分、随机状态和已经投出的骰面。
3. 分开实现“统计这组六颗装备用了几颗各类骰子”和“创建含基础物品的行囊”。不能直接让通用 `createInventory` 无条件补六颗：它也被装备数量校验调用，会把需求数量算错。
4. 选项显示“公平骰 · 持有 6 · 已装备 5 · 空闲 1”。对不可选物品显示原因，例如“全部已装备”“另一槽位已佩戴”“核心最多一枚”。增加“全部换回公平骰”和明确的徽章卸下入口。
5. 允许在已有物品中替换徽章；仅持有一枚时明确提示。保持最多两枚、最多一枚核心和不重复佩戴的限制。交换徽章位置可以先卸下再装，第一轮修订不必引入自动交换逻辑。
6. 入座时一次性校验并复制整套配置，实际投掷采用提交的配置。满载之手的临时第七颗骰不计入持有量。

旧档应先验证类型、整数数量和物品 ID，再补基础公平骰；不能用迁移掩盖未知物品、负数或特殊骰库存不足等损坏数据。

## 3. 建议的铜筹账簿规则

要达到“三个 1 = 500”，需要调整当前允许拆分的规则。建议将改动限定在铜筹账簿的新版本，继续保留合法组合枚举、DFS 搜索和其他核心的最优拆分机制。

**建议的新规则：佩戴铜筹账簿时，同一次选择中，同一面值最多按两颗单骰计分；其余骰子必须被合法的同点组合或顺子消费。单骰翻倍、同点与顺子减半的倍率保持原值。**

这意味着三个 1 不能全部拆成单骰；如果其中一个 1 被顺子使用，剩下的两个 1 仍可作为单骰。约束针对实际选中的本次新骰，玩家只选两颗 1 时仍得 400 分，分次投掷锁定的骰子也不会被追溯合并。

| 本次选择 | 当前账簿规则 | 建议新规则 |
| --- | ---: | ---: |
| 1 | 200 | 200 |
| 1、1 | 400 | 400 |
| 1、1、1 | 600 | **500** |
| 5、5、5 | 300 | **250** |
| 1、1、1、1 | 1000 | 1000 |
| 1、1、Joker | 500 | 500 |
| 1、1、1、5、5、5 | 900 | **750** |
| 1、1、1、2、3、4、5 | 650 | 650：一组五骰顺子 250，加两颗单骰 400 |
| 七颗 1（满载之手） | 4200 | 4200：六同 4000，加单骰 200 |

实现时通过通用 Modifier 规则接口提供这项约束，计分器不硬编码徽章名称。DFS 的状态与缓存必须包含影响后续单骰可选数量的信息，确保在受限规则下仍能找到最高合法分数。预览、锁定、落袋和模拟决策共用同一计分结果。

更新徽章示例及规则说明，直接展示“三个 1 按三同计 1000 × 0.5 = 500”，并解释不能拆成三个单骰。测试同时覆盖三个 5，避免只修正一个特例。
